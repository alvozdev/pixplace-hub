Новый воркфлоу их уже содержит и делит месяц по дням так же, как старые: clipart 1–10 / 11–20 / 21–31, fashion 1–15 / 16–31, interior и products на одном вебхуке. В админке Make заполнять не нужно. ## Почему я не выбираю ключи OpenRouter и Runware в нодах сам

Я посмотрел старые воркфлоу: ключи в них лежат в «учётках» n8n, это отдельное закрытое хранилище. Коннектор n8n умеет создавать и менять воркфлоу, но в это хранилище не пускает. Через него не видно даже названий учёток, поэтому их нельзя поставить в ноду. Так сделано в самом n8n. Доступ есть к воркфлоу, а не к ключам.

## Что такое «строка из админки»

Это пароль, по которому n8n узнаёт панель. Админка → «Связь панели с n8n» → «Сгенерировать», строка появляется в поле → скопировать → «Сохранить».

## Дальше два варианта, выбери любой

### А. Сделать самому, около 3 минут, один раз

Открой https://alv-n8n.pixplace.space/workflow/qjUtSGUAe9gPMkj1:

1. **Generate Webhook:** дважды нажми на ноду → в поле Credential выбери «Create new» → Name: `x-hub-token`, Value: строка из админки → Save. Сейчас там стоит чужая учётка «JsonCut Api», её заменяешь.
2. **Publish Webhook:** выбери ту же учётку.
3. **Analyze Idea Image** и **Write Style Variants:** выбери в списке ту же учётку OpenRouter, что стоит в старых воркфлоу.
4. **Render Variant:** выбери учётку Runware.

### Б. Дать доступ к ключам n8n, тогда всё это делаю я, сейчас и в будущем

В n8n: Settings → n8n API → Create API key. Ключ не присылай в чат, а добавь в настройки облачной среды (меню среды в заголовке сессии → Edit):

- секрет `N8N_API_KEY` = ключ n8n;
- секрет `HUB_N8N_TOKEN` = строка из админки;
- в Allowed domains: `alv-n8n.pixplace.space`.

Подхватится в новой сессии, дальше учётки и включение воркфлоу на мне.
